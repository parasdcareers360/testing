# Weekly Review

> **Type:** Template — fill in every Sunday evening (or your last study session of the week).
> One filled-in example is below the template.

## Template

```markdown
## Week <N> Review (<start date> – <end date>)

**Planned focus:** <from 12_week_plan.md>
**Actual hours logged:** <n>h (target: ~18-20h)

### Completed
- DSA: <problems solved this week, by pattern>
- Non-DSA: <files/topics covered>
- Trackers updated: <which ones>

### Not completed / pushed to next week
- <item> — reason: <ran out of time / too hard, needs more foundational work / deprioritized>

### Scorecard (1-5, self-rated)
| Area | Score | Note |
|---|---|---|
| DSA speed/correctness | | |
| DSA communication (explaining out loud) | | |
| System design fundamentals | | |
| Python depth | | |
| Backend/SQL | | |
| Behavioral story readiness | | |

### Biggest win this week
<one sentence>

### Biggest gap this week
<one sentence — feed this into next week's plan and, if it's a coding gap, into mistake_log.md>

### Adjustment for next week
<what you're changing about the plan or schedule, if anything>
```

## Worked example

```markdown
## Week 4 Review (2026-09-14 – 2026-09-20)

**Planned focus:** Intervals, Trees & BSTs; system design fundamentals begin
**Actual hours logged:** 16h (target: ~18-20h) — lost ~3h to a work deadline Thursday

### Completed
- DSA: 6 problems (4 Intervals, 2 Trees) — all logged in problem_tracker.md
- Non-DSA: capacity_estimation.md, api_design.md read; first mock interview (coding) done
- Trackers updated: problem trackers x2, mistake_log.md (1 entry), weakness_tracker.md (1 entry)

### Not completed / pushed to next week
- BST problem_tracker.md — only 2/10 attempted, ran out of time — push 2 more into week 5

### Scorecard (1-5, self-rated)
| Area | Score | Note |
|---|---|---|
| DSA speed/correctness | 3 | still slow on tree recursion, need more reps |
| DSA communication (explaining out loud) | 2 | mock interview feedback: jumped to code too fast |
| System design fundamentals | 3 | capacity estimation still feels shaky |
| Python depth | 4 | comfortable so far |
| Backend/SQL | 4 | closest to day job, feels natural |
| Behavioral story readiness | 3 | 6 stories drafted, need more Amazon LP mapping |

### Biggest win this week
Finished Intervals pattern cleanly, including two Hard problems without hints.

### Biggest gap this week
Mock interviewer flagged that I start coding before fully stating the approach out loud — need to
force a verbal "here's my plan" step before touching the keyboard.

### Adjustment for next week
Add a hard rule: state approach out loud (or in comments) before writing code, every single
practice problem, not just mocks.
```
