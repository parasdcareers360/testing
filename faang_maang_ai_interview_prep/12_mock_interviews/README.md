# 12 — Mock Interviews

> **Type:** Template hub — see each file

Mocks are where prep gets tested under real conditions (time pressure, a stranger watching, no
notes). Everything here is a template you fill in after each mock, plus two trackers that turn
individual mocks into a feedback loop instead of a series of one-off events.

| File | Purpose |
|---|---|
| [`coding_mock_interview_template.md`](coding_mock_interview_template.md) | Fill in during/after every coding mock |
| [`system_design_mock_interview_template.md`](system_design_mock_interview_template.md) | Fill in during/after every system design mock |
| [`behavioral_mock_interview_template.md`](behavioral_mock_interview_template.md) | Fill in during/after every behavioral mock |
| [`interview_feedback_rubric.md`](interview_feedback_rubric.md) | What a FAANG/MAANG-style interviewer is actually scoring you on, per round type |
| [`weakness_tracker.md`](weakness_tracker.md) | Recurring weaknesses across mocks — the thing you actually fix |
| [`mistake_log.md`](mistake_log.md) | Every concrete mistake, one row each, fed by `daily_checklist.md` and mocks alike |

## Cadence

See [`../00_master_plan/mock_interview_schedule.md`](../00_master_plan/mock_interview_schedule.md)
for when to start and how many to run. The short version: don't wait until you "feel ready" — your
first coding mock should happen by week 3, first system design mock by week 7, because the
*feedback* is the point, not the score.

## The loop

1. Do the mock.
2. Fill in the relevant template immediately (same day — memory of what went wrong decays fast).
3. Pull every concrete mistake into `mistake_log.md`.
4. If a mistake repeats 2+ times, promote it into `weakness_tracker.md` and make it a explicit
   focus for the following week in
   [`../00_master_plan/weekly_review.md`](../00_master_plan/weekly_review.md).
