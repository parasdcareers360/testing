# Weakness Tracker

> **Type:** Template — copy or fill in directly

A weakness earns a row here once it's shown up **2+ times** in `mistake_log.md` or mock feedback —
this file is for patterns, not one-off slips. Review it every
[`weekly_review.md`](../00_master_plan/weekly_review.md) and close a row out when it stops
recurring for 2+ consecutive weeks.

| Weakness | First noticed | Times recurred | Status | Fix in progress |
|---|---|---|---|---|
| | | | Open / Improving / Closed | |

## Worked example

| Weakness | First noticed | Times recurred | Status | Fix in progress |
|---|---|---|---|---|
| Skips testing/tracing example before declaring "done" on coding problems | 2026-09-08 | 3 | Improving | Forcing an explicit "let me trace through an example" step out loud on every practice problem, not just mocks |
| Runs long on capacity estimation in system design (10+ min instead of ~5) | 2026-09-21 | 2 | Open | Practicing estimation drills with a hard 5-minute timer, round numbers only |
| Failure-story answers trail off without a clear "what changed afterward" | 2026-09-15 | 1 | Open | Rewriting all failure/conflict stories in `story_bank_tracker.md` to end on an explicit change made |
