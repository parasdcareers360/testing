# YouTube Channels and Blogs

> **Type:** Study notes

Free, ongoing content — good for staying current between structured study sessions, not a
replacement for the pattern-based work in this workspace.

## DSA / coding interviews

- **NeetCode (YouTube)** — pattern-based problem walkthroughs that map directly onto
  [`02_dsa_and_coding/patterns/`](../02_dsa_and_coding/patterns/); if a `concept.md` isn't
  clicking, search the pattern name there.
- **Back To Back SWE (YouTube)** — slower, more intuition-focused explanations, good for patterns
  where you understand the code but not the *why* (DP and backtracking especially).

## System design

- **ByteByteGo (YouTube and blog)** — short, visual explainers on the same building blocks covered
  in [`06_system_design/fundamentals/`](../06_system_design/fundamentals/) (caching, load
  balancing, sharding).
- **The System Design Primer (github.com/donnemartin/system-design-primer)** — technically a repo,
  but reads like a structured blog/course; cross-reference with
  [`useful_github_repos.md`](useful_github_repos.md).

## Engineering blogs (real production trade-offs)

- **High Scalability (highscalability.com)** — real company architecture write-ups, good
  supporting material for the trade-off discussions expected in
  [`06_system_design/exercises/`](../06_system_design/exercises/).
- **Individual company engineering blogs (e.g. Netflix Tech Blog, Uber Engineering, Stripe
  Engineering)** — read 1-2 posts closely rather than skimming many; a specific real-world
  incident write-up teaches more about trade-offs than a generic explainer.

## AI / LLM systems

- **Anthropic's engineering blog and OpenAI's engineering blog** — closest primary sources for
  `09_ai_backend_and_llm_systems/` topics like RAG architecture, evaluation, and observability.
- **Chip Huyen's blog (huyenchip.com)** — practical ML/LLM-in-production writing, complements the
  book referenced in `books_and_courses.md`.

## Python

- **Python's own "What's New" changelogs (docs.python.org)** — the most reliable source for
  version-specific behavior questions that come up in `03_python_core_and_advanced/`, better than
  a blog that may be out of date.

## How to use this list

Treat these as supplementary, not primary — the workspace files are written to be
interview-sufficient on their own (per [`../STYLE_GUIDE.md`](../STYLE_GUIDE.md)). Reach for one of
these only when a specific concept isn't clicking from the concept file's own explanation.
